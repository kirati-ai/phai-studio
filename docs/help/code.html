เขียนโค้ดกับ control

ฟอร์มที่ออกแบบได้ struct ชื่อ <ฟอร์ม>Ui ที่มี control ทุกตัวตาม Id และ trait <ฟอร์ม>Events ที่มีเมธอดสำหรับทุกเหตุการณ์ โค้ดของคุณอยู่ในไฟล์ <ฟอร์ม>.rs ไฟล์เดียว ไฟล์ _ui.rs สร้างใหม่ทุกครั้งที่บันทึก ห้ามแก้

Properties, Methods, Events

control แต่ละตัวเป็น object แบบ WinForms มีสามอย่าง

อย่างคืออะไรตั้งที่ไหน
Propertiesลักษณะ: ข้อความ สี ตำแหน่ง ใช้งานได้ไหม มองเห็นไหมหน้าต่าง Properties (⚙) เก็บในไฟล์ .phf
Methodsสั่งให้ทำ: ui.name.set_text("..."), ui.ok.focus()ในโค้ด
Eventsบอกเมื่อเกิดขึ้น: คลิก พิมพ์ กดปุ่ม เลือกแถวแท็บ Events (⚡) ดับเบิลคลิกชื่อเหตุการณ์ได้เมธอดว่างพร้อมพารามิเตอร์

ชนิดของ control ในโค้ด

field ใน Ui เป็นชนิดจาก phai_ui::ctl ตรงกับชื่อใน WinForms ช่องเลือก object บนหน้าต่าง Properties บอกชนิดไว้ เช่น name phai_ui::ctl::TextBox

impl MainWindowEvents for MainWindow {
    fn save_clicked(&mut self, ui: &MainWindowUi) {
        if ui.name.text().trim().is_empty() {
            ui.name.focus();
            return;
        }
        ui.orders.items_add(&[&ui.name.text(), &ui.qty.value().to_string()]);
        ui.status.set_part_text(0, &tf("{0} orders", &[&ui.orders.items_count()]));
        ui.save.set_enabled(false);
    }
}

เหตุการณ์ที่มีข้อมูลมาด้วย

บางเหตุการณ์ส่ง args มาด้วย เหมือน e ใน C#

fn name_key_down(&mut self, ui: &MainWindowUi, e: &phai_ui::events::KeyEventArgs) {
    if e.key == 0x0D {             // Enter
        e.set_handled();           // ไม่ต้องให้ช่องกรอกจัดการต่อ
        self.save_clicked(ui);
    }
}

fn main_window_form_closing(&mut self, ui: &MainWindowUi, e: &phai_ui::events::ClosingEventArgs) {
    if self.changed {
        ui.status.set_part_text(0, "บันทึกก่อนปิด");
        e.cancel();                // ยังไม่ปิด
    }
}

ชนิด args: KeyEventArgs, KeyPressEventArgs, MouseEventArgs, ClosingEventArgs, ItemEventArgs, FileDropEventArgs

งานที่ใช้เวลานาน: thread กับ invoke

อย่าทำงานนาน ๆ (อ่านไฟล์ใหญ่ ต่อเน็ต คิวรีฐานข้อมูล) ในเมธอดของเหตุการณ์ หน้าต่างจะค้าง ให้ทำบน thread อื่น แล้วส่งผลกลับมาแก้หน้าจอด้วย invoke เพราะ control ของ Windows แก้ได้เฉพาะจาก thread ของหน้าต่าง

fn load_clicked(&mut self, ui: &MainWindowUi) {
    let invoker = ui.invoker();                    // ส่งข้าม thread ได้
    std::thread::spawn(move || {
        let rows = read_big_file();                // งานหนัก บน thread อื่น
        MainWindowUi::begin_invoke(invoker, move |me: &mut MainWindow, ui: &MainWindowUi| {
            ui.list.fill(&rows);                   // กลับมาบน thread ของหน้าต่าง
            me.loaded = true;
        });
    });
}
  • begin_invoke ส่งงานไปแล้วทำต่อเลย ไม่รอ ได้ทั้งตัวโปรแกรม (me) และ control (ui)
  • invoke แบบเดียวกัน แต่รอจนงานบนหน้าต่างเสร็จ
  • งานที่ไม่ต้องใช้ me หรือ ui: invoker.begin_invoke(move || ...)
  • หน้าต่างปิดไปแล้ว งานที่ส่งมาทีหลังจะถูกข้ามไปเอง

พิมพ์น้อยลง: use phai_ui::prelude::*;

ไฟล์โค้ดของทุกฟอร์มมีบรรทัด use phai_ui::prelude::*; อยู่แล้ว (Studio ใส่ให้) ของที่ใช้บ่อยจึงเรียกชื่อสั้นได้เลย ไม่ต้องพิมพ์ phai_ui::form:: นำหน้า:

message_box(ui.hwnd, "บันทึกแล้ว", "ร้านค้า", MessageBoxButtons::Ok, MessageBoxIcon::Information);
if message_box(ui.hwnd, "ลบไหม?", "ร้านค้า", MessageBoxButtons::YesNo, MessageBoxIcon::Question) == DialogResult::Yes { /* ลบ */ }
ui.status.set_part_text(0, &tf("สวัสดี {0}", &[&name]));

หรือเรียกผ่าน ui ของฟอร์มก็ได้ — พิมพ์ ui. แล้วเลือกจากรายการ: ui.alert("บันทึกแล้ว") กล่องข้อความมีปุ่ม OK ใช้ชื่อหน้าต่างเป็นหัวเรื่อง, if ui.confirm("ลบไหม?") { ... } ถามใช่/ไม่ใช่ ได้ true เมื่อตอบใช่, ui.prompt("ชื่อ?", "") ถามให้พิมพ์ — ชื่อเดียวกับ alert confirm prompt ของ JavaScript, ui.message_box("ลบไหม?", "ร้านค้า", MessageBoxButtons::YesNoCancel, MessageBoxIcon::Warning) แบบเลือกปุ่มและไอคอนเอง (พิมพ์ ui:: ก็ได้ Studio เปลี่ยนเป็น ui. ให้)

ที่ได้มาด้วย: message_box, MessageBoxButtons, MessageBoxIcon, DialogResult, t, tf และชนิดของ e ในเมธอดของ event (KeyEventArgs, MouseEventArgs, PaintEventArgs ...) — บนเว็บก็ใช้ได้ (กล่องข้อความเป็นของเบราว์เซอร์)
